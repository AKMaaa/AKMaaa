# システム構成

Akira Maeda のポートフォリオ・研究実績サイト。Astro で静的生成し、microCMS の内容をビルド時に取り込み、GitHub Pages で配信する。

見た目の正は [デザインルール.md](./デザインルール.md)（Web サイト用）。ルートの `DESIGN_RULES.md` は GitHub プロフィール専用。

## 目的

- ニュース・研究発表・作品・経歴を静かな複数ページで公開する
- よく増える本文は CMS、変わりにくい経歴・スキルはコード側
- `<username>.github.io` のルート配信（`base` 設定は使わない）

## 技術スタック

| 層 | 採用 | 備考 |
| --- | --- | --- |
| SSG | Astro 7（minimal） | `output: static`。Node.js `>=22.12.0` |
| CMS | microCMS | SDK: `microcms-js-sdk` |
| ホスティング | GitHub Pages | GitHub Actions（`withastro/action`） |
| フォント | Shippori Mincho + Cormorant Garamond | 和文タイトル／細い欧文 UI |
| 言語 | TypeScript / Astro | `tsconfig` は `astro/tsconfigs/strict` |

## サイトマップ

コンテンツは **ジャンル別ページ** に分ける（1 ページに全部載せない）。Fremen の photographs / books と同じ発想。

| パス | ナビ | 内容 | データ |
| --- | --- | --- | --- |
| `/` | （氏名リンク） | トップ。画像 1 枚のみ（額装） | `public/images/` |
| `/news` | `news` | 短報一覧 | microCMS `news`（`content`/`publishedAt` 対応） |
| `/research` | `research` | 研究成果・紹介文 | microCMS `research` + 静的リード |
| `/works` | `works` | アプリ・Web 作品 | microCMS `works` |
| `/photographs` | `photographs` | 写真 | `src/data/photographs.ts` |
| `/hobbies` | `hobbies` | 趣味 | `src/data/hobbies.ts` |
| `/profile` | `profile` | 簡単なプロフィール・経歴フィルター・スキル | `src/data/bio.ts` |
| `/contact` | `contact` | メール・Facebook・フォーム | `src/data/bio.ts` |

`/bio` は `/profile` へ 301 リダイレクト。

### ジャンル分けの考え方

- **全部を1リストにしない。** 研究は `research`、制作物は `works`、近況は `news`、人の情報は `profile`
- ナビでジャンルを選び、Main ではそのジャンルだけを時系列で見せる
- 詳細な業績の正本は [researchmap](https://researchmap.jp/akira-maeda)。サイトは抜粋・入り口

## 環境変数（microCMS）

| キー | 入れ方 |
| --- | --- |
| `MICROCMS_SERVICE_DOMAIN` | **`xxxx` だけ**（`xxxx.microcms.io` の先頭）。`.microcms.io` は付けない |
| `MICROCMS_API_KEY` | API キー |

例: 管理画面 URL が `https://my-portfolio-akmaaa.microcms.io` なら、ドメイン値は `my-portfolio-akmaaa`。

## データフロー

```text
microCMS (news | research | works)
        │  getList / orders: "-date"
        ▼
src/library/microcms.ts
        ▼
src/pages/{news,research,works}.astro  +  BaseLayout
        ▼
astro build → dist/ → GitHub Pages
```

`/` と `/profile` はビルド時に CMS を叩かない。ランタイムでの CMS 呼び出しはしない。

## microCMS

認証未設定・プレースホルダー・API 失敗時は空配列を返し、ページは「投稿がまだありません」を出す。ビルドを落とさない。

既存の `activities` / `getActivities` は移行用に残してよい。ページからは下記 API を参照する。

### `news`

| フィールド | 型 | 必須 | 用途 |
| --- | --- | --- | --- |
| `id` | `string` | はい | ID |
| `title` | `string` | はい | 見出し |
| `date` または `publishedAt` | `string` | どちらか | 並び・表示日（お知らせテンプレは `publishedAt`） |
| `body` または `content` | `string` | いいえ | 本文（テンプレは `content`） |
| `link` | `string` | いいえ | 外部リンク |

取得の対応関係:

| microCMS プレビュー | SDK | サイトでの用途 |
| --- | --- | --- |
| `GET /api/v1/news` | `getList({ endpoint: 'news' })` → `getNews()` | `/news` 一覧 |
| `GET /api/v1/news/{id}` | `getListDetail(...)` → `getNewsDetail(id)` | 個別（必要なら） |

ドメインは `my-portfolio-akmaaa` のみ（`.microcms.io` は付けない）。

### `research`

| フィールド | 型 | 必須 | 用途 |
| --- | --- | --- | --- |
| `id` | `string` | はい | ID |
| `title` | `string` | はい | 見出し |
| `date` | `string` | はい | 並び・表示日 |
| `venue` | `string` | いいえ | 学会・会場 |
| `role` | `string` | いいえ | 発表 / 共著など |
| `summary` | `string` | いいえ | 概要（HTML 可） |
| `link` | `string` | いいえ | 外部リンク |

### `works`

| フィールド | 型 | 必須 | 用途 |
| --- | --- | --- | --- |
| `id` | `string` | はい | ID |
| `title` | `string` | はい | 作品名 |
| `date` | `string` | いいえ | 公開・制作日 |
| `summary` | `string` | はい | 短い説明 |
| `stack` | `string` または `string[]` | いいえ | 技術（表示は読点区切り） |
| `url` | `string` | いいえ | 公開 URL |
| `repo` | `string` | いいえ | リポジトリ URL |

スキーマ変更時は `src/library/microcms.ts` と microCMS 管理画面を同時に更新する。

## デプロイ

1. `main` への push、または workflow_dispatch
2. `actions/checkout@v7` → `withastro/action@v6`（CMS Secrets を渡す）
3. `actions/deploy-pages@v5`

Pages の Source は GitHub Actions。`package-lock.json` はコミット必須。

## ローカル

```bash
npm install
npm run dev      # http://localhost:4321/
npm run build
npm run preview
```

## 拡張時の方針

- CMS 連携は `src/library/` に集約する。ページから SDK を直接呼ばない
- レイアウト・ナビは `BaseLayout` に集約する
- 見た目は `Agent.d/デザインルール.md` に従う
- 一覧が 100 件を超える場合は `getAllContents` への切り替えを検討する
- 秘密情報をクライアントバンドルやリポジトリに出さない
